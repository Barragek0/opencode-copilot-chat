## Overview

Release `0.5.2` is a hotfix cut driven primarily by the DeepSeek V4 multi-turn `reasoning_content` regression that ships in the current Marketplace build (`0.5.1`). The fix (PR #123) landed on `main` on 2026-08-10 but has not been released, so every OpenCode user running DeepSeek V4 Flash in Copilot Chat still hits:

```text
HTTP 400: The reasoning_content in the thinking mode must be passed back to the API
```

on every follow-up turn after the first thinking turn. DeepSeek V4 Flash is the most-used model in the OpenCode ecosystem, and surfacing it inside Copilot Chat is the core value proposition of this extension, so the fix must ship.

The cut also bundles the Agents window + provider management work (#122 / #125, #121 / #124), the vision proxy cache (#120), and the reasoning-history test extraction (#126).

## Cut Steps

Each gate requires explicit maintainer approval (per project rules: no auto-commit, no auto-push, no auto-publish).

### Step 1 — Merge pending PRs

```bash
gh pr merge 126 --repo ltmoerdani/opencode-copilot-chat --merge   # merge commit, NEVER squash
gh pr merge  91 --repo ltmoerdani/opencode-copilot-chat --merge   # dependabot patch
git pull origin main --ff-only
```

### Step 2 — Bump version

Edit `package.json`:

```diff
- "version": "0.5.1",
+ "version": "0.5.2",
```

### Step 3 — Finalize CHANGELOG

Move the `[Unreleased]` block to a dated section:

```markdown
## [0.5.2] — 2026-08-11
```

Add the 0.5.2-specific entries if any were missing (the reasoning test extraction from #126 goes under `### Changed`).

### Step 4 — Verify

```bash
npm run compile   # MUST be clean (no errors)
npm test          # MUST pass (expected 177/177 after #126)
npm run lint      # MUST be clean
```

If any of these fail, stop and triage before continuing.

### Step 5 — Commit the release prep

```bash
git add package.json CHANGELOG.md docs/
git commit -m "chore(release): 0.5.2 cut — version bump + changelog"
```

**Requires explicit user approval** before running. Do not push until approved.

### Step 6 — Tag

```bash
git tag -a v0.5.2 -m "0.5.2"
```

### Step 7 — Publish to Marketplace

```bash
vsce login ltmoerdani      # or use PAT
vsce publish 0.5.2
```

**Requires explicit user approval.** This is a destructive public action.

### Step 8 — Push

```bash
git push origin main --follow-tags
```

**Requires explicit user approval.**

## Rollback Plan

If the published 0.5.2 build is broken:

1. Do not un-publish from the Marketplace (it breaks installed users). Instead, cut a hotfix `0.5.3` with the revert.
2. `git revert` the offending commit on `main`, bump to `0.5.3`, re-publish.
3. Document the rollback in a new issue doc.
